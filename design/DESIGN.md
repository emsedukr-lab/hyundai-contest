# Pleos Connect Design System

> **출처** — `Pleos_Connect_design_assets_215.fig` (Foundation·Components, 2026-10-16 export) · `Pleos Connect display guide 2.1.5` (Form factors & Display, 2026-09-30 export)
> **추출 방식** — Figma 파일의 변수(Variables)·스타일·컴포넌트 세트를 직접 파싱해 값 그대로 옮겼습니다. 색상 HEX는 `#RRGGBB` 또는 `#RRGGBBAA`(뒤 2자리가 알파)입니다.
> **단위** — 모든 치수는 **Connect-S 17"(2560×1440, 160dpi, 1dp = 1px)** 기준 dp, 글자는 sp입니다. 다른 폼팩터 값은 [Layout › 폼팩터 스케일](#폼팩터-스케일) 참고.
> **동반 파일** — Variant별 전체 레이어 스펙과 폼팩터 4종의 컴포넌트 사이즈 토큰 전체는 `DESIGN-reference.md`에 있습니다.

## Overview

Pleos Connect는 현대자동차그룹(Hyundai · Kia · Genesis) 차량용 인포테인먼트(IVI) 플랫폼의 디자인 시스템입니다. 파일에서 읽히는 성격은 다음과 같습니다.

- **주행 중 한눈에 읽히는 큰 UI** — 본문이 26–30sp, 버튼 높이가 64/80/100dp, 터치 타깃(체크박스·라디오·아이콘 버튼)이 최소 64dp입니다. 최소 글자 크기는 20sp입니다.
- **무채색 중심** — 화면은 `#131417`(잉크) ↔ `#FFFFFF` 사이의 그레이 11단계와 그 알파 값으로만 구성하고, 유채색은 상태·정보(활성 초록, 긍정 파랑, 부정 주황빨강, 자율주행 보라)와 법규 표시에만 씁니다.
- **Light / Dark 완전 대칭** — 모든 토큰이 Light·Dark 두 값을 갖습니다. Basic 스케일은 테마에서 값이 뒤집히므로(`basic/00` = Light 흰색, Dark 잉크) 토큰만 쓰면 다크가 자동 대응됩니다.
- **윈도우 기반 화면** — 앱은 전체 화면이 아니라 시스템이 배치하는 **Landscape / Portrait 앱 윈도우** 안에서 실행됩니다. 윈도우 밖(상태바, 주행 정보, GNB)은 시스템 영역입니다.
- **둥근 형태와 얕은 깊이** — 반경 16/24/32(컨트롤), 40(앱 윈도우), 48(팝업·알림). 깊이는 3단계 그림자와 1–2dp 반투명 보더로만 표현합니다.
- **폼팩터 4종 대응** — 같은 컴포넌트가 `connect-s / connect-l / connect-w / connect-waterfall` 모드별 사이즈 토큰을 갖습니다.

## Colors

### 구조

1. **Basic (Scale) 토큰** — 의미 없는 원색 스케일. Grayscale(`basic/*`), Alpha(`alpha/*`), Static(`static/*`).
   _"Scale Token은 프로덕트의 일관된 색상 체계를 정의하는 표준화된 컬러 토큰입니다. 특별한 시맨틱한 성격이나 맥락을 갖고있지 않은 경우에 사용"_ (파일 원문)
2. **System (Semantic) 토큰** — 용도가 담긴 토큰. Basic을 참조(alias)합니다. _"시맨틱 토큰은 UI와 컬러가 전달하고자 하는 의도와 맥락을 담고 있습니다."_ (파일 원문)

토큰 이름은 Figma 변수 표기(`button/basic/enabled`)로 적었습니다. 파일의 Colors 문서 페이지는 같은 토큰을 스네이크 표기(`button_basic_enabled`)로 적습니다 — `/`를 `_`로 바꾸면 됩니다.

### 사용 원칙

- **텍스트·아이콘은 4단계 위계**로 씁니다: `primary`(100%) → `secondary`(84%) → `tertiary`(64%) → `quaternary`(32%). _"모든 텍스트 정보에 같은 컬러를 쓰는 경우, 유저가 읽어야 할 정보의 우선순위를 파악하기 어려워 혼란을 줄 수 있습니다."_ (파일 원문)
- `text/dark/*`·`icon/dark/*`는 밝은 면 위(기본), `text/light/*`·`icon/light/*`는 어두운 면(채워진 버튼, 토스트 등) 위에 씁니다. 둘 다 테마에 따라 자동 반전됩니다.
- 비활성 상태의 글자·아이콘은 `text/dark/quaternary` / `icon/dark/quaternary`입니다(컴포넌트 공통).
- **Divider** — _"섹션이나 항목 간에 구분을 위해 활용되거나, 디자인 요소를 감싸는 Border에 사용"_. 컴포넌트 보더는 대부분 `divider/secondary`입니다.
- **Surface** — _"컨텐츠와 정보들을 감싸고있는 컬러. Z축의 가장 하위에 위치"_.
- **Informative** — _"정보의 중요도, 진행·완료·오류 등을 나타낼 때 사용"_. 켜짐/선택은 `informative/active`, 텍스트 버튼·링크는 `informative/positive`.
- **Regulation** — _"텔테일, 온도 등 법규를 만족시킬 수 있는 정보에 사용"_. 컴포넌트 중에서는 텍스트 필드의 오류 상태(보더·도움말)만 `regulation/red`를 씁니다.

## Typography

- **서체** — 디자인 파일의 텍스트 스타일은 **Asta Sans**로 정의되어 있습니다. 실제 차량에서는 브랜드별 시스템 폰트(위 표)로 치환됩니다.
- **굵기 이름** — `Extra_Strong` = ExtraBold(800), `Strong` = Bold(700), `Normal` = Regular(400).
- **자간** — 0%. 예외: `Driving/Speed_kmh`, `Driving/Traffic_Sign`은 −3%.
- **최소 크기** — _"Android 접근성 가이드라인 권장 최소값은 12sp … 가독성을 위해 일반적으로 1.5배 이상 … 실제 픽셀 기준 최소 높이: 18px 이상"_ (파일 원문). 시스템 스케일의 최솟값은 `Label/Small` 20sp입니다.

| Style | 값 | 쓰이는 곳 |
|---|---|---|
| `Shadow/Light/Level1` | `0 6 24 #00000014` (8%) | 앱 윈도우, 드롭다운, 스테퍼, 슬라이더, 스위치 노브 |

## Components

표 읽는 법 — 컴포넌트 세트마다 **크기·구조**(Variant 중 치수가 같은 것끼리 묶음)와 **상태·색**(색이 같은 것끼리 묶음) 두 표가 있습니다. `Container`는 컴포넌트 자체, `Parts`는 내부 레이어(`›`가 깊이)입니다. `row/col`은 오토 레이아웃 방향, `pad`는 위아래/좌우(또는 상/우/하/좌), `r`은 반경, `border N`은 보더 두께입니다. 색은 Light 값 기준 토큰명이며 Dark 값은 [Colors](#colors) 표를 따릅니다. `‹…›`는 안에 들어간 다른 컴포넌트의 Variant입니다.

## Do's and Don'ts

파일에 명시된 규칙과, 컴포넌트 값에서 일관되게 확인되는 패턴만 적었습니다.

**Do**
- 색은 System 토큰을 먼저 쓰고, 맞는 의미가 없을 때 Basic 토큰을 씁니다. HEX를 직접 쓰지 않습니다.
- Light·Dark 둘 다에서 확인합니다. `basic/*`·`alpha/*`는 테마에서 반전되고 `static/*`만 고정입니다.
- 텍스트·아이콘 색은 primary → quaternary 위계로 정보 우선순위를 구분합니다.
- 글자는 정의된 스케일(20–60sp)만 쓰고, 20sp 미만은 쓰지 않습니다.
- 터치 가능한 요소는 높이 64dp 이상으로 둡니다(컴포넌트 최솟값).
- 앱 화면은 Landscape·Portrait 윈도우 크기 모두, 그리고 대상 폼팩터의 윈도우 크기에 맞춥니다.
- 치수는 폼팩터 토큰으로 지정해 `connect-s / l / w / waterfall`에서 함께 스케일되게 합니다.
- 눌림 상태는 `…/pressed` 토큰 또는 `dim/dark/secondary` 겹침으로 표현합니다.
- Overlay 위에 올라가는 요소에는 테마에 따라 변하지 않는 `static/*`을 씁니다.

**Don't**
- `regulation/*` 색을 장식·강조색으로 쓰지 않습니다(문서상 텔테일·온도 등 법규 정보용, 컴포넌트에서는 입력 오류 표시에만 사용).
- 유채색을 장식용으로 쓰지 않습니다. 강조는 굵기·크기·명도 위계로 합니다.
- 그림자를 3단계 스타일 밖으로 새로 만들지 않습니다.
- 상태바·GNB·Driving View 영역을 앱 콘텐츠로 침범하지 않습니다(시스템 영역).
- 앱 아이콘에 마스크 형태를 직접 그려 넣지 않습니다(시스템이 브랜드별로 마스킹).

## 부록 — 원본 파일의 불일치와 주의점

옮기면서 확인된 항목입니다. 구현 전에 원 디자인 담당에게 확인이 필요할 수 있습니다.

1. **Alpha 문서 표기와 변수명이 반대** — Colors 문서 페이지의 Alpha 표는 `#131417` 계열을 `basic_alpha_light_*`로 적지만, 실제 변수와 System 토큰 표는 `alpha/dark/*`로 씁니다. 이 문서는 변수 기준입니다.
2. **문서 표와 변수 값이 다른 System 토큰 (⚠)** — `button/switch/pressed`(Dark), `button/switch/disabled`(Dark), `controller/stepper_background`(Dark), `keyboard/normal/secondary_pressed`(Dark), `keyboard/static/secondary_pressed`·`background`·`icon_light`·`icon_dark`·`text`. 이 문서는 변수 값을 적었습니다.
3. **문서 페이지의 토큰명 오기** — Icon·Text 표의 뒤쪽 4행이 `…_dark_…`로 중복 표기되어 있어 `…/light/…`로 바로잡았습니다. 그 외 원문 철자는 그대로 두었습니다: `controller/slider/knop`, `divider_teritary`(변수는 `divider/tertiary`), `gearshitft_background`, `icon_sqaure`, `goast_button`, `State=Diabled`.
4. **변수가 없는 문서 토큰** — `surface/low`, `informative/negative`, `regulation/green·yellow·orange·bluetooth`, `climate/*` 대부분, `driving/*`, `phone/*_pressed`, `media/*_primary` 등은 문서 표에만 있고 이 파일의 변수로는 포함되지 않아, 문서 표가 가리키는 Basic 토큰으로 값을 계산해 적었습니다.
5. **Media 그라데이션 표기** — 문서의 `#00FFFFFF`, `#FF1D1E21`는 ARGB 순서로 보여 `#FFFFFF00`, `#1D1E21`로 옮겼습니다(변수 값과 일치).
6. **Feature Font** — `Driving/Traffic_Sign`과 `Gleo AI/List_Number`는 문서 표와 스타일 정의의 굵기·크기가 다릅니다(Typography 절 참고).
7. **Waterfall 플랫폼 토큰** — display guide의 일부 변수 컬렉션에는 Waterfall이 3072 × 680(또는 3840 × 850)으로 남아 있으나, Form factors 표와 실제 프레임은 3072 × 816입니다. 이 문서는 표·프레임 기준입니다.
8. **시스템 팝업의 `Extended` Variant** — `Extended=True`가 더 작은 치수(720/1000 × 308, 반경 40)로 그려져 있습니다. 이름의 의미(예: W-Extended용)는 파일에 설명이 없습니다.
9. **Light 모드 값 기준** — 컴포넌트 표의 그림자 스타일명은 `Shadow/Light/*`만 정의되어 있습니다(Dark 전용 그림자 스타일 없음).
