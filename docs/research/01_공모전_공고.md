## 1. 공모 개요

### 1.1 명칭·주최·목적

- **명칭:** 현대자동차그룹 차량용 앱 개발 공모전
- **슬로건:** `Code your App into Pleos App Market`
- **주최:** 현대자동차그룹
- **목적:**
  > 차량 데이터와 기능, 이동 상황을 활용해 운전자와 탑승자에게 새로운 경험을 제공하는 앱 서비스를 발굴하고 개발하는 공모전입니다.
- 공식 포스터의 공모전 과제:
  > Pleos Playground 공개 API를 활용한 차량용 앱 아이디어 · 개발
- 위치·경로·주행 상태·차량 상태 등 자동차의 데이터와 기능을 활용하는 차량용 앱을 제안·개발합니다.
- 공고일부터 공개된 Pleos Playground 개발 문서로 아이디어 기획과 개발을 시작할 수 있습니다.

### 1.2 주제

**아래 예시에 한정하지 않으며, 별도의 주제 구분 없이 자유롭게 지원할 수 있습니다.**

- **모빌리티 & 라이프 편의**
  - 주행 중에도 끊김 없는 주문 · 픽업 · 주차 등 일상 서비스 경험
- **인카 엔터테인먼트**
  - 주행 맥락과 결합된 몰입형 미디어 · 사운드 경험
- **스마트 드라이빙 & 안전**
  - 차량 이상 징후의 조기 인지와 실시간 안전운전 피드백
- **패밀리 & 동승자 케어**
  - 장거리 이동을 즐겁게 만드는 어린이 · 가족 동승자 케어
- 출퇴근, 여행, 충전, 주차, 가족과의 이동, 반려동물 동반, 휴식, 업무 등 다른 이동 상황도 제안할 수 있습니다.

### 1.3 전체 진행 구조

1. **1차 · 서류심사**
   - 접수양식인 기획서를 제출합니다.
   - 개발 산출물은 선택 제출이며 가산점이 있습니다.
   - 서류심사를 거쳐 **20팀**을 선정합니다.
2. **2차 · 최종 PT 심사, 오프라인 발표**

   - **실제 동작 가능한 앱 시연이 필수**입니다.
3. **최종 10팀 선정**
   - 현대자동차그룹 행사 전시·시연 및 공식 시상식에 참여합니다.
   - 순위는 2차 PT 결과물을 기준으로 확정하고, **2027.02 행사에서 발표**합니다.

## 2. 참가 자격·팀 구성

- **참가 대상:** `대학(원)생 · 일반인 · 스타트업`
- **참가 형태:** `개인 또는 팀(팀은 대표자 포함 최대 5인)`
- **시상 부문:** `대학생 / 일반(스타트업 포함)`
- 공식 접수양식의 참가 부문 표기는 다음과 같습니다.
  - `대학(원)생`
  - `일반(스타트업 포함)`
- 공식 포스터에서는 참가 대상을 `대학(원)생 및 소프트웨어 개발자`로 표현합니다.

### 2.2 현대자동차그룹 임직원

공지 원문:

> 심사의 공정성을 위하여 현대자동차그룹 임직원은 공모전 참가는 가능하나, 최종 수상(시상 및 상금 수여) 대상에서는 제외됩니다

### 2.3 팀 참가 시 필수사항

- 대표자를 포함한 참가자 전원의 정보를 접수양식에 작성합니다.
- **대표자와 팀원 전원이 각각 동의 여부·본인 서명·서명일자를 작성**해야 합니다.
- 대표자는 **팀원 전원을 참조수신(CC)**하여 제출해야 합니다.
- 접수양식 원문:
  > 팀원 각자의 동의 여부와 본인 서명이 필요하며, 참조수신만으로 동의를 대체하지 않습니다.
- CC에 포함된 이메일 주소는 같은 팀의 다른 수신자에게도 표시되므로 제출 전에 팀원에게 안내해야 합니다.
- 팀장은 출품작 제출·심사·공모전 요강에서 정한 이용에 관한 모든 팀원의 동의를 받아야 합니다.
- 운영자가 요청하면 동의를 확인할 수 있는 자료를 제출해야 합니다.
- 팀 내부 역할·기여도·상금 분배 등 분쟁은 팀 내부에서 해결하며 운영자는 관여하지 않습니다.

## 5. 접수양식의 구성·작성 요건

공식 DOCX는 크게 다음 네 부분으로 구성됩니다.

### 5.1 `01 참가신청서 · 운영 접수용`

#### A. 참가 기본정보

- 참가 단위: 개인 / 팀
- 참가 부문: 대학(원)생 / 일반(스타트업 포함)
- 팀명, 개인 참가 시 성명
- 앱명 / 프로젝트명
- 대표자 성명
- 역할
- 대표자 소속
  - 학교/학과/회사명/무소속 등
  - **필수기입 아님**
- 대표자 이메일
- 대표자 휴대폰번호
- 참가 인원
- 작성일

#### B. 참가 구성원

대표자를 포함한 전원이 작성합니다.

- 성명
- 소속
- 휴대폰 번호
- 이메일 주소
- 담당 역할

원문:

> 운영용 연락정보는 이 신청서에만 기재하고, 다음 장의 작품 소개에는 기재하지 않습니다.

> 주민등록번호·신분증·상세주소 등은 본 신청서에서 요구하지 않습니다.

### 5.2 `02 앱 프로젝트 소개 / 심사 자료`

**익명 심사 자료 작성 요건**

> 대표자·구성원의 성명, 연락처, 이메일, 소속은 기재하지 않습니다. 해당 정보는 01 참가신청서에만 기재해 주세요.

## 7. 개발환경·SDK·에뮬레이터

### 7.1 플랫폼과 기본 요구사항

- **Pleos:** 현대자동차그룹의 소프트웨어 중심 모빌리티 브랜드
- **Pleos Connect:** 차량용 인포테인먼트 플랫폼
- **Pleos Playground:** 개발 문서·도구·가이드를 제공하는 개발자 포털
- **Pleos Connect SDK:** Pleos Connect 환경의 차량용 앱 개발 도구
- SDK는 **Android Automotive OS, AAOS 기반**입니다.

공모전 개발환경 페이지 원문:

> Pleos 개발 문서의 개발 환경 요구사항 기준으로 Android API 28 이상, Gradle 8.0 이상, Java 또는 Kotlin을 사용합니다. 문서와 대응하는 SDK 버전도 같은 페이지에 있습니다.

공식 환경 설정 문서의 요구사항:

- **Minimum Android SDK:** `Android API 28 이상`
- **Gradle 버전:** `8.0 이상`
- **개발 언어:** `Java, Kotlin`
- **Pleos Connect Emulator 버전:** `2.1.0`
- **Virtual Console을 지원하는 Emulator 최소 버전:** `2.1.0`

minSdk 요구 이유:

> 이는 차량 사이버 보안 요건(사이닝 키 로테이션·리니지 지원)에 따른 요구사항입니다.

**주의:** 앱의 **minSdk 28**과 에뮬레이터 시스템 이미지의 **API 34**는 서로 다른 항목입니다.

### 7.4 Android Studio·에뮬레이터 설치 순서

1. **Android Studio 최신 버전**을 설치하고 Android Emulator 시스템 요구사항을 확인합니다.
2. 기존 Pleos Connect Emulator가 있으면 **기존 버전을 삭제 후 설치**합니다.
3. `Tools > SDK Manager > SDK Update Sites > +`에서 추가합니다.
   - Name:
     ```text
     Pleos Connect System Image
     ```
   - **Mac**
     ```text
     https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-arm64-sys-img.xml
     ```
   - **Windows/Linux**
     ```text
     https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml
     ```
4. `SDK Platforms`에서 **Android API Level 34**의 Pleos Connect system Image를 선택합니다.
   - `Show Package Details` 활성화
   - 설치 후 **Android Studio 재시작**
5. `Tools > Device Manager > Create device > Automotive > Pleos Connect v2.1.0`
   - 구버전 메뉴명: `AVD Manager`, `Create Virtual Device`
6. 고급 설정:
   - `Startup > Default boot > Cold`
   - RAM **4 GB**
   - 구버전: `Graphics > Hardware`, `Boot option > Cold boot`
7. Device 탭에서 API **34**, `Pleos Connect v2.1.0 APIs` 선택 후 Finish
8. Device Manager에서 AVD 실행
9. 앱 프로젝트 생성:
   - `File > New > New Project > Car 또는 Automotive > Empty Activity`
   - 빠른 시작 예제는 **Kotlin**, Minimum SDK **API 28 이상**
10. app 모듈의 정상 빌드를 확인한 뒤 SDK 의존성·권한을 추가하고 동기화합니다.
11. 에뮬레이터가 완전히 부팅된 후 실행 대상으로 선택해 Run으로 빌드·설치·테스트합니다.

### 7.6 Virtual Console

- 지원 최소 에뮬레이터: **v2.1.0**
- 에뮬레이터 실행 후:
  ```sh
  adb forward tcp:8088 tcp:8088
  ```
- PC 브라우저 접속:
  ```text
  http://127.0.0.1:8088/
  ```
- 기어·브레이크·스티어링·도어·창문·시트·조명·배터리·공조 등의 상태와 이벤트를 시뮬레이션할 수 있습니다.
- 차량 상태 변경에 대한 앱 반응, 제어 명령, 반복 테스트·데모에 사용합니다.
- 접속 오류 시:
  - 에뮬레이터 실행 및 지원 이미지 확인
  - `adb devices` 확인
  - 포트 포워딩 재실행
  - **8088 포트 충돌** 확인

**콘솔에서 시뮬레이션할 수 있다는 사실이 상용 배포 앱의 권한 승인까지 뜻하지는 않습니다.**

### 7.8 권한과 SDK별 제약

#### 공통: App Market 배포 권한

SDK 개요 원문:

> 퍼미션은 Pleos App Market과 사전 협의 및 승인된 범위 내에서만 사용할 수 있습니다. 승인되지 않은 퍼미션을 선언하거나 해당 API를 호출하는 경우 앱 심사를 통과할 수 없습니다.

- **매니페스트 권한 선언**, **SDK 사용 신청**, **App Market 승인**, **음성 서버 앱 등록**은 구분해야 합니다.
- 이 문구만으로 공모전 에뮬레이터 테스트에도 동일한 별도 승인이 필요하다고 확대 해석할 수는 없습니다.
- 반대로 이번에 확인한 웹 문서만으로 모든 테스트 권한이 승인 없이 허용된다고 확정하지도 않았습니다.

출처: [SDK 개요](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/)

#### Vehicle

- `AndroidManifest.xml`에 다음 형식의 권한을 선언합니다.
  ```text
  pleos.car.permission.{상수명}
  ```
- `CAR_*`: 조회, get
- `CONTROL_CAR_*`: 제어, set
- 사용하는 도메인의 권한만 선언하고 개별 API의 `@RequiresPermission`을 확인해야 합니다.
- 지원 여부는 도메인별 `checkXXXCapabilities`로 확인합니다.
- 권한 누락 시 `onFailed` 예외 또는 `ERROR_SECURITY_PERMISSION`이 발생할 수 있습니다.
- 빠른 시작의 도어 조회 테스트는 `pleos.car.permission.CAR_DOORS`를 사용합니다.
- 비동기 콜백이 끝나기 전에 `release()`하지 않고 SDK 사용 종료 시점에 해제합니다.
- Vehicle 기능이 Android Automotive에 수용되는 경우 **“최소 2개 major version 동안 backward compatibility”**를 보장한다고 안내합니다.

#### TextToSpeech·SpeechToText

권한:

```text
pleos.car.permission.TTS_SERVICE
pleos.car.permission.STT_SERVICE
```

모드:

- **HYBRID**
  - 기본 모드
  - 서버 우선, 네트워크 실패 시 On-device로 자동 전환
- **SERVER**
  - 네트워크·앱 등록 필요
  - 실패 시 On-device로 전환하지 않음
- **ON_DEVICE**
  - 네트워크 불필요
  - 이 모드만 사용하면 서버 앱 등록 불필요

서버 사용 시에는 Client ID·Client Secret으로 SDK 초기화 후 `registerApp()`을 호출하고, `onConnected()` 이후 서버 요청을 수행합니다.

#### FusedLocation

- 사용 전 **`isSupported()` 확인 필수**
- 미지원 환경에서는 해당 기능을 제공하지 않도록 처리
- 마지막 위치 조회·위치 업데이트·근접 영역 진입·이탈 알림 등을 지원
- `getLastKnownLocation()`은 새 위치 계산 API가 아니며 데이터가 없으면 **null 가능**
- 권한:
  ```text
  pleos.car.permission.FUSED_LOCATION
  ```
- 보호 수준: **dangerous**
- 매니페스트 선언과 앱 권한 요청·결과 처리가 필요합니다.
- 개인정보 설정에서 차단됐을 때 `showLocationAccessBlockedPopup()`은 **안내만 하며 접근 허용 API가 아닙니다.**
- `null`, `onError(Exception)`을 처리하고 화면·기능을 제한해야 합니다.

원문:

> Android의 ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION, ACCESS_BACKGROUND_LOCATION에 관한 동작과 포그라운드·백그라운드 위치 접근 정책은 이 SDK 문서에서 별도로 보장하지 않습니다. Google Fused Location SDK의 설명을 Pleos Connect의 동작 보장으로 해석하면 안 됩니다.

## 11. 출품 유의사항·금지사항·실격·지식재산권

### 11.1 창작물·허위 기재·접수 오류

유의사항 공지 원문:

> 모든 출품작은 참가자의 순수 창작물이어야 하며, 제3자의 작품 일부 또는 전부를 표절한 작품이거나 기 발표된 타 공모전 수상작은 심사 대상에서 제외됩니다

> 제출한 서류에 기재한 내용이 사실과 다를 경우 선정이 취소될 수 있습니다

> 신청기간 마감일 이후에 제출된 서류는 인정되지 않으며, 지원자의 실수로 인한 파일 오류와 파손 등으로 발생되는 모든 책임은 지원자에게 있습니다

> 잘못된 개인정보 입력으로 인해 공모전 응모가 정상적으로 완료되지 않는 경우 그 책임은 응모자에게 있습니다

> 응모 과정 등에서 응모자의 고의 또는 과실로 발생하는 법적 문제는 응모자가 책임지며, 입상된 이후라도 응모 과정 등에서 이러한 법적 문제가 있었음이 밝혀질 경우 수상 취소 및 상금이 환수됩니다

### 11.2 이용약관의 금지행위 전체

1. 타인의 계정, 개인정보, 저작물을 무단으로 사용하는 행위
2. 허위 사실을 기재하거나 출품작의 내용을 사실과 다르게 표시하는 행위
3. 자동화된 수단으로 사이트에 접근하거나 데이터를 수집하는 행위
4. 서비스의 정상적인 운영을 방해하거나, 취약점을 이용해 권한을 넘어선 정보에 접근하는 행위
5. 관련 법령이나 이 약관을 위반하는 그 밖의 행위

위반 시 경고·일시 이용 정지·이용계약 해지·출품작 실격 등의 조치를 할 수 있습니다.

공지 원문:

> 주최측은 수상 아이디어에 대하여 「지식재산권 양도 등에 대해 결과 발표일로부터 4개월 동안 우선적으로 협상할 수 있는 권리(이하 "우선협상권"이라 한다)」를 가질 수 있다

> ※ 주최자는 비영리 공익적 목적으로 입상작을 복제 및 전송할 수 있고, 입상자와 별도의 합의를 통한 이용허락을 얻어 2차적 저작물을 작성할 수 있으며, 입상작을 이용한 수익 창출행위를 할 수 있다. 주최자가 공모전 요강에 공고된 범위를 넘어 입상작을 이용할 경우 입상자와 별도 합의하여 정한다

## 15. 미기재·불일치·추가 확인이 필요한 사항

### 15.1 제출 관련

- **심사용 GitHub 계정명**
  - “공지된 심사용 GitHub 계정”이라고만 되어 있고 구체적인 이름은 확인되지 않았습니다.
- **제출 페이지**
  - GitHub 안내의 “제출 페이지 입력”과 실제 이메일 접수 절차가 혼재합니다.
- **익명성과 외부 링크**
  - DOCX는 공유 링크·첨부자료에서도 개인정보·계정정보·개발자 실명을 노출하지 말라고 합니다.
  - GitHub·숏폼 계정명 처리에 대한 구체적인 예외나 비식별화 절차는 확인한 안내에 없습니다.
- 확인한 안내에는 일반 시연 영상의 **파일 확장자·코덱·해상도·용량·길이 제한**, 이메일 첨부 총용량, 기획서 파일명 규칙이 별도로 기재되어 있지 않습니다.
  - **숏폼 영상의 길이·방향 요건은 별도로 존재**합니다.
- 공식 양식은 DOCX지만, PDF 등 대체 제출 형식의 허용 여부는 명시적으로 확인되지 않았습니다.
- 소개 자료는 **분량 제한 없음**이 DOCX에 명시되어 있습니다.

### 15.2 참가·심사 관련

- 대학생·일반인이 섞인 팀의 **부문 판정 기준**은 확인한 안내에 없습니다.
- 2차 PT의 **세부 평가기준·발표 시간·질의응답 시간**은 확인되지 않았습니다.
- 1차 항목별 배점과 단계별 가산점 수치는 공개되지 않았습니다.
- 전시 준비 기간의 추가 제출물·기한·세부 보완 범위는 추후 공지 예정입니다.
- **2027.02 행사 및 시상식의 정확한 날짜·장소**는 확인한 안내에 없습니다.

### 15.3 개발 관련

- Vehicle SDK가 빠른 시작 **2.3.1**, 개별 설정 문서 **2.3.2**로 다릅니다.
- SDK 소개 목록에 있는 기능 중 일부는 사용 신청 문서에서 **준비 중**입니다.
- 특정 Android Studio 버전, Android Gradle Plugin 버전, JDK 버전, Kotlin 버전, 필수 targetSdk·compileSdk 수치는 확인한 환경표에 없습니다.
