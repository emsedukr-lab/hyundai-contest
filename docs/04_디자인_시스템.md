# 04 디자인 시스템

색·글꼴·모서리·컴포넌트 모양의 기준은 **`design/TOSS.md`**(토스 디자인 시스템 시각 언어, 2026-11-14 사용자 결정)이고, 차량의 치수·글자 크기·화면 구역·주행 규칙은 **`design/DESIGN.md`**(Pleos Connect 2.1.5 공식 디자인 에셋 명세, 상세 표 `design/DESIGN-reference.md`)를 그대로 따릅니다. 2026-11-14에는 디자인 체계만 바꿨고 화면 배치·흐름·문구·기능은 그대로입니다(이전: Pleos 명세 전면 적용). 두 화면이 같은 단어를 같은 순서로 보여 주도록 문구를 맞췄습니다.

## 1. 차량: TOSS.md(색·모양) + DESIGN.md(치수·글자) → Compose

2026-11-14에 차량 앱의 **디자인 체계만** 토스 시각 언어(`design/TOSS.md`)로 바꿨습니다. 화면 배치·흐름·문구·기능은 그대로이고, 치수·글자 크기·화면 구역·주행 규칙은 Pleos 명세를 그대로 지킵니다.

### 지키는 규칙 (TOSS.md + Pleos 안전 기준)

- **색은 `tn_*` 역할만.** 코드에 hex가 없습니다. 화면 바탕 `canvas`(회색), 카드 `surface`(흰 면), 팝업 `surface-float`.
- **강조는 토스 블루 하나.** `accent`는 주 버튼(FILLED) 채움·진행 막대·스위치 켜짐·동선 스케치의 강조하는 날에, 파란 글자 `accent-text`는 고정 시각·자물쇠·정보 태그에만 씁니다.
- **시맨틱 색은 뜻이 있을 때만.** 초록 `positive` 여유·완료, 빨강 `negative` 늦음·충돌·삭제 확인, 주황 `warning`은 확인 필요의 점뿐(글자는 잉크).
- **평면.** 카드·머리말·출발/숙소 바에 보더·그림자·아래 구분선이 없습니다. 그림자는 떠 있는 것(선택된 세그먼트·스위치 노브 = Level1, 팝업 = Level3)에만, Pleos 오프셋·블러에 낮은 알파 navy(`tn_shadow_1`·`tn_shadow_3`).
- **옅은 면은 놓인 곳보다 한 단계.** 카드 위 `fill-weak`, 회색 바탕 위 `fill-weak-on-canvas`, 팝업 위 `fill_weak_on_float`. `Screen`·`PleosCard`·`PleosSystemPopup`이 `LocalLayer`를 정하고 버튼·태그·트랙·번호 원은 `weakFace()`로 고릅니다. **눌림은 한 단계 진하게, 비활성은 컴포넌트 전체 30%.**
- 차량에만 둔 역할(값은 모두 TOSS.md의 회색 사다리): `fill_weak_on_canvas_pressed`·`fill_weak_on_float(_pressed)`(위 규칙), `switch_knob`(흰 노브), `shadow_1`·`shadow_3`.
- **모양은 반경 8·12·16·20·24·32·48·999, 간격은 4·8·12·16·20·24·32·40·48만.** `Space`·`Radius`가 Pleos 토큰을 그대로 돌려줍니다. 코드에 남은 숫자 dp는 QR 크기(연결 규격 24-7)뿐입니다.
- **글자는 Pleos 스케일(20~60sp)만, 20sp 미만 없음. 터치 요소는 64dp 이상.**
- 주·야간, Landscape(1700)·Portrait(840) 창 모두 대응. 두 칸 배치는 창이 Portrait 폭(`window/apps/portrait_width`)보다 넓을 때입니다.

### 화면 구조

- **첫 화면**: 머리말 '떠날지도' + [모바일 여행 불러오기](FILLED) [설정](BASIC). '다음 여행' 카드: '8일 뒤 출발'/'여행 중 · 2일차'/'지난 여행'(굵은 글자), 이름, '기간 · n박 n일 · 장소 n곳', 오른쪽에 전 일정 동선 스케치, 아래 '충돌 n'·'확인 필요 n' 태그와 버전. 그 아래 '다른 여행' 목록.
- **여행 상세**: 머리말(‹ + 이름 + '기간 · n박 n일 · v1'), 일차 세그먼트 컨트롤. 넓은 창은 **왼쪽 55% 하루 동선**, **오른쪽 45% 다음 목적지 패널**(이름 Title Large, 도착 예정, 상태 태그, [다음 목적지 안내](FILLED), [오늘 경로 전송] [도착 처리] [여기서 출발](BASIC)) → 출발 전 점검 → 확인할 점 → [이 여행 삭제](BASIC Small). 좁은 창(840dp)은 다음 목적지 → 출발 전 점검 → 동선 → 확인할 점 순서로 쌓습니다.
- **불러오기**: 단계 막대 QR 스캔 1/4 → 코드 비교 2/4 → 여행 승인 3/4 → 완료 4/4. QR은 항상 흰 면(`tn_qr_background`)에 검정 모듈(`tn_qr_module`), 확인 코드는 옅은 면 상자 안 큰 숫자.
- **설정**: 머리말(‹ + '설정'), 스위치 행, [모든 여행 삭제](BASIC Small), 에뮬레이터 전용 시연, 정보.
- **주행 중**: 카드 하나에 '다음 목적지 · 2일차', 이름(Headline), 남은 거리, 상태 한 줄과 큰 상태 태그, 쉬어 가기 권고. 버튼 없음.

### 화면 규칙

- 문장·단락은 3줄 이하입니다(`PleosText` 기본 `maxLines = 3`).
- 최상위 Back은 앱을 닫지 않고 숨깁니다(`moveTaskToBack`).
- 주행 중에는 QR·요약·안내 버튼을 숨기고, 시선을 끄는 애니메이션은 쓰지 않습니다. 팝업은 주차 중에만 띄웁니다.
- 시간 지킴이 상태는 태그 색으로 보입니다: 여유 = 초록 태그, 빠듯·확인 불가 = 주황 점 + 잉크 글자 태그, 늦음 = 빨간 태그. 문구에 "여유 66분", "27분 늦을 수 있어요"가 함께 있어 색 없이도 뜻이 통합니다.
- 시연 시각이 켜져 있으면 목록·상세 위에 태그 "시연 시각 11/21 09:00 · 에뮬레이터 전용"을 항상 표시합니다.

화면: `docs/evidence/2026-11-14_toss-design/car/`(바꾸기 전 `before-*`, 바꾼 뒤 `after-*` — 주간·야간·팝업·주행·불러오기), 이전 Pleos 색 화면은 `docs/evidence/2026-11-12_pleos-design-spec/`, 불러오기 흐름은 `docs/evidence/2026-11-05_car-import-qr/`.

## 3. 휴대폰: Astryx + 토스 테마

- **토스 시각 언어로 교체**(2026-11-14, 디자인 체계만 — 배치·흐름·문구·기능 그대로): Astryx 0.7.15, 테마 `src/tossTheme.ts` → `astryx theme build` → `src/toss.css`. 색은 `shell.css` `:root`의 `--tn-*` 역할 변수(`design/TOSS.md` §2, `light-dark()`) 한 곳에만 있고 다른 CSS·TSX에는 hex가 없습니다. 글꼴은 Pretendard Variable(OFL) 92개 가변 조각 자체 호스팅(`public/fonts/pretendard`, 원격 참조 0건). 회색 바탕 위 흰 카드(보더·그림자 없음), 주 버튼은 토스 블루 채움(화면당 하나), 보조는 옅은 회색, 칩 선택은 잉크 채움, 세그먼트는 흰 칸 + 그림자, 태그는 옅은 바탕 + 같은 색 글자(확인 필요는 주황 점 + 잉크 글자), 지도·동선은 블루 경로 + 흰 테두리, 삭제 확인만 빨강. '꼭' 핀은 정보 태그(옅은 파랑) — 빨강은 오류 전용. 본문 15px, 입력값 17px, 가장 작은 글자 12px, 시각·거리는 고정폭 숫자. 아래 그 전에 만든 항목들의 색·모서리·글꼴 값은 이 기준으로 바뀌었습니다. 화면 `docs/evidence/2026-11-14_toss-design/web`(전후, 라이트·다크).

컴포넌트는 Astryx를 그대로 쓰고(접근성·입력 동작 유지), 색·글꼴·모서리는 차량 앱과 같은 **Pleos Connect 2.1.5 공식 토큰**(`design/android-res`)을 휴대폰 크기(차량 dp × 0.6)로 옮겨 입혔습니다. 기준 화면은 FHD 세로 폰(1080×1920, CSS 폭 360–412pt)이고, 넓은 화면에서는 가운데 최대 480pt로 둡니다.

- **`design/DESIGN.md` 규칙에 맞춤**(2026-11-12, 구조·문구는 그대로, 스타일만): 차량과 같은 결정을 0.6배로 적용했습니다. 아래 그 전에 만든 항목들에 적힌 색 띠 태그·파랑 고정 표시·주황 점·그래파이트 칩·모서리 16/20/24는 이 표의 값으로 바뀌었습니다.

  |---|---|

남고, 카드를 누르거나 Esc로 닫힘. 세로로 끌면 그냥 스크롤, 밀고 난 직후의 탭은 상세를 열지 않음. 장소 상세에도 '일정에서 빼기'(키보드·스크린리더 경로). **영업시간**: 카카오 검색으로 넣은 장소의 상세에 '카카오맵에서 영업시간 보기 ↗'(새 창) + 그 아래 '영업시간 직접 입력'. **장소 추가는 오른쪽 아래 플로팅 + 버튼**: 일차 선택 없이 **새 장소 찾기 → 저장 목록 → 즐겨찾기** 순서의 시트. 고른 장소는 모두 **전체 일정**(날짜 미정)에 담기고 시트는 열린 채 '…을(를) 저장 목록에 담았어요'가 뜸(여러 곳을 이어서 담기). 저장 목록 행을 누르면 장소 상세가 열리고, **일차는 장소 상세의 '일차' 선택칸**(전체 일정 / N일차 · 날짜, 고르면 그날 끝에 붙음, 전체 일정으로 되돌리면 되돌리기 스낵바)이나 경로 추천으로만 정함. 즐겨찾기는 모든 여행 공통 목록(누르면 담기, 이미 담긴 곳은 '담김', ★로 빼기, 검색 결과 ☆로 추가). 버튼 배지 = 일정에 없는 장소 수(고정 시각인데 일정에 없으면 경고색). 드롭다운은 칸 바로 아래에 열림(`placement="below"`). **메모·입퇴실**(휴대폰 전용): 숙소는 입실·퇴실 시간(선택)과 '메모 (호실 등)', 다른 장소는 '메모'를 남기고 카드에 회색 줄로 보임(다음 날 출발 카드엔 전날 숙소 퇴실 시각). 장소 상세의 '장소 삭제'는 중립 버튼이고 확인 단계만 빨간색. 지도 시트의 날 선택은 탭 대신 셀렉트. 입력은 바텀 시트(출발·이동 시간·숙소/귀가·장소 추가·지도/차로 보내기), 경고는 해당 카드에 한 줄. 하단: 저장(변경 있을 때) ↔ 경로 보고 차로 보내기, 나갈 때는 자동 저장. 더보기 메뉴: 경로 추천·이동시간·거리 다시 계산·복제·공유·삭제 |
| 연결 (`/c`) | 진행 바(연결/코드 확인/여행 선택/보낼 정보/보내기) · `SelectableCard` · `Switch` · `MetadataList` |
| 개인정보 (`/privacy`) | 읽기 전용 목록 |

- 다크 모드는 `prefers-color-scheme`를 따릅니다. 화면 확인은 360×640 @3x(=1080×1920)·412×732 @2.625x에서 라이트·다크로 합니다.

## 5. 대비 점검

`python3 tools/contrast.py`가 차량 앱이 실제로 쓰는 토큰 조합(`tn_colors.xml`)을 주간·야간으로 계산합니다(2026-11-14 기준 모두 통과).

- 본문·보조 문구·태그·팝업·QR: 모두 4.5:1 이상 (최저 주간 늦음 태그 4.69:1).
- 토스 블루·빨강 버튼 위 흰 글자는 3.6~3.7:1로, 차량 버튼 글자가 모두 26sp 굵게 이상(큰 글자, 기준 3:1)이라 허용합니다. 휴대폰 주 버튼 글자는 17px 굵게입니다.
- 그래픽(색 점·꺼진 스위치·구분선)은 3:1 미만인 것이 있어 뜻은 항상 글에 둡니다("충돌 ·", "확인 필요 ·").

## 6. QR 인식 시험

| 조건 | 방법 | 결과 |
|---|---|---|
| Pleos 에뮬레이터 2560×1440, 야간 테마, 앱 Landscape 창 | 화면 캡처 → jsQR 해독 | **성공** — 세션 URL과 일치 (`tools/e2e-car.mts`) |
| 주행 시연 중 | 같은 방법 | QR 없음(해독 불가) 확인 |
| iPhone 기본 카메라 / Android 기본 카메라 / 카카오톡·네이버 스캐너 | Mac 화면의 에뮬레이터 QR 촬영 | **미시험** — 실제 폰 필요 |
| 앱 안 스캐너(연결 탭, jsQR) | 헤드리스 Chrome 가짜 카메라(y4m)에 이 앱 형식 QR | **성공** — 권한 허용 → 해독 → `/c` 연결 화면, 다른 QR 거절, 닫으면 카메라 트랙 종료, 권한 거부 안내. 실제 폰 카메라는 미시험 |
| 밝기·거리·각도 | 실차 화면 | **미검증** — 실차 확보 불가. Mac 화면은 실차와 반사·각도가 다름 |

인앱 브라우저나 일부 스캐너는 URL fragment를 버릴 수 있습니다. 그러면 휴대폰은 "QR을 다시 스캔해 주세요 · 휴대폰 카메라로"를 보여 줍니다.
