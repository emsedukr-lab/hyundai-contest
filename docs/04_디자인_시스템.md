# 04 디자인 시스템

차량은 **Pleos Connect 2.1.5 공식 디자인 에셋**을, 휴대폰은 **Astryx 컴포넌트 + Pleos 모바일 테마**를 따릅니다. 두 화면이 같은 단어를 같은 순서로 보여 주도록 문구를 맞췄습니다.

## 1. 차량: Pleos 토큰 → Compose

| 출처 | 앱에서 쓰는 방식 |
|---|---|
| `design/source/*.fig` (공식 2종) | `design/tools/fig_*.py`로 변수·스타일을 추출 → `design/android-res/` |
| `@color/pleos_*` (232개, 주·야간) | `colorResource(R.color.pleos_*)`. 야간은 `values-night`가 자동 적용 |
| `@dimen/pleos_*` (Connect-S, 791개) | 버튼 높이·패딩·반경, 팝업 폭·반경, 간격(`pleos_common_*`) |
| `TextAppearance.Pleos.*` (24개) | 실행 중 스타일을 읽어 Compose `TextStyle` 생성 (글자 크기 배율·야간 전환 때 다시 읽음) |
| Asta Sans 가변 폰트 | `FontVariation.weight`로 400/500/700/800 |

Gradle `syncPleosRes` 작업이 `design/`의 리소스를 빌드 폴더로 복사해 등록합니다. `design/`이 유일한 출처라서 값이 어긋나지 않습니다.

### 컴포넌트

| 컴포넌트 | 근거 에셋 | 구현 |
|---|---|---|
| `PleosButton` | ivi_basic_button (Primary/Secondary × L/M/S × 눌림/비활성) | `pleos_button_filled_*`/`pleos_button_basic_*` 색, `pleos_buttons_basic_*` 높이·패딩·반경·최소폭 |
| `PleosSystemPopup` | ivi_system_popup (제목·설명·확인/취소) | `pleos_popup_system_medium_width`, 반경 48dp, 그림자 Level3, 설명 3줄 이하 |
| `PleosCard` | 표면 + Shadow/Light/Level1 | `pleos_surface_basic`, 반경 `pleos_radius_l` |
| `PleosHeader` | ivi_title (Main/Depth) | Title Large + 보조 문구 |
| `StatusLine` | informative/regulation 색 | 정상 `informative_active`, 주의 `regulation_orange`, 충돌 `informative_negative` |

### 화면 규칙

- 문장·단락은 3줄 이하입니다(`PleosText` 기본 `maxLines = 3`).
- 주요 정보는 Title Medium(36/44) 이상, 본문은 Body(26~30) 크기입니다.
- 앱 영역 1000dp 이상이면 두 칸(Landscape 1700dp), 미만이면 한 칸(Portrait 840dp)으로 바꿉니다.
- 최상위 Back은 앱을 닫지 않고 숨깁니다(`moveTaskToBack`).
- 주행 중에는 QR·요약·안내 버튼을 숨기고, 시선을 끄는 애니메이션은 쓰지 않습니다.
- 주행 중 여행 상세는 카드 하나(다음 목적지 Title Large + `StatusLine` 한 줄)만 남깁니다. 버튼·스크롤·팝업이 없고, 상태가 바뀌어도 글자만 바뀝니다.
- 시간 지킴이 상태줄은 기존 `StatusLine` 색을 그대로 씁니다: 여유 = positive, 빠듯·확인 불가 = 주의(orange), 늦음 = 충돌(negative). 색만으로 구분하지 않도록 문구에 "여유 46분", "47분 늦을 수 있어요"를 함께 씁니다. 새 색을 추가하지 않아 대비 점검 결과(5장)는 그대로입니다.
- 시연 시각이 켜져 있으면 목록·상세 위에 "시연 시각 11/21 09:00 · 에뮬레이터 전용"을 항상 표시합니다.
- 터치 크기는 공식 dp 값이 없어서 버튼 높이 토큰(Medium 80dp, Large 100dp)을 따릅니다.

## 3. 휴대폰: Astryx + Pleos 모바일 테마

컴포넌트는 Astryx를 그대로 쓰고(접근성·입력 동작 유지), 색·글꼴·모서리는 Pleos 모바일 지침으로 다시 입혔습니다. 기준 화면은 FHD 세로 폰(1080×1920, CSS 폭 360–412pt)이고, 넓은 화면에서는 가운데 최대 480pt로 둡니다.

- **테마**: `src/pleosTheme.ts`를 `astryx theme build`로 `pleos.css`로 만듭니다. 흰 캔버스와 회색 섹션 면(`#f7f8fa`/다크 `#1d1e21`), 강조색은 파랑 하나(`#0064ff`/다크 `#0082ff`), 모서리 12·14·20·24.
- **글꼴**: Asta Sans(42dot, OFL)를 93개 가변 조각으로 자체 호스팅해 화면에 필요한 조각만 받습니다. 원격 폰트 참조는 빌드 결과물에 0건이고 CSP는 `default-src 'self'`를 유지합니다.
- **앱 구조**(toss.md 메뉴 구성): 왼쪽 정렬 56pt 상단 바 + 하단 플로팅 탭 4개(여행 `/` · 장소 `/places` · 연결 `/car` · 설정 `/settings`). 탭에서 여는 화면(여행 편집, `/add`, `/c`, `/privacy`, 설정 하위)은 뒤로 버튼이 있는 푸시 화면이고, 채운 버튼은 화면 아래 하나뿐입니다.
- **카테고리 안의 메뉴: Stacked cards**. 섹션 제목 아래 메뉴를 하나씩 카드로 나눕니다. 모든 카드는 같은 너비·같은 왼쪽 선(섹션 제목과 같은 24pt)·12px 간격이고(stageshow 'Stacked cards' 규칙), 카드는 회색 섹션 면(모서리 20), 아이콘 칸은 흰색입니다. 글은 단어 단위로 줄바꿈합니다(`keep-all`). 설정·여행 목록·연결·장소 탭에 쓰고, 읽기 전용 안내문인 개인정보 화면은 목록으로 둡니다.

| 화면 | 구성 |
|---|---|
| 여행 (`/`) | 내 여행 카드(버전·미배정 배지) · **오른쪽 아래 플로팅 + = 새 여행 만들기**(탭바 위, M34). 샘플 메뉴 없음(시연·시험은 `/?sample=1`) |
| 장소 (`/places`) | 붙여넣어 담기 → `/add` 흐름 재사용 · 지도 앱에서 담기 · 즐겨찾는 장소 |
| 연결 (`/car`) | 진행 중인 연결 이어가기 · 보내는 법 3단계 · 최근 보낸 여행 |
| 설정 (`/settings`) | 출발 장소(집 주소·회사·즐겨찾기 1~3 → `/settings/place/:slot`) · 데이터(백업·가져오기·친구 공유 받기) · 앱 |
| 여행 편집 | **탭 없는 한 화면**(M30): 위에서 아래로 `여행 정보` → `1일차` → `2일차` … 를 이어서 스크롤하고, 각 구역 머리말(`N일차 · 11/20(금)`, 확인할 점이 있으면 점, 오른쪽 [지도])이 스크롤하는 동안 상단 바 아래에 고정됨. 제목 줄 `이름 · 11/16–11/17 · 1박 2일 ✎`을 누르면 맨 위로. **여행 정보**(M32에서 타임라인 스타일로 통일, M33: 저장된 여행은 기본 **접힘** — 요약 카드 `이름 / 기간 · N박 M일 / 출발 … → 귀가 … / 숙소 n/n박(미정이면 경고)`, 머리말의 '펼치기/접기'나 요약 카드·제목을 누르면 펼쳐서 수정, 새 여행은 펼친 상태): 머리 카드(여행 이름을 큰 글자로 그 자리에서 입력 + 기간) 아래로 타임라인과 같은 점선 레일·마커·회색 카드로 출발 → 일차별 숙소 → 귀가(카드마다 작은 머리글, 셀렉트 옆 연필 = 설정). 고른 숙소는 이름·회색 입퇴실/메모 줄로 보이고 '+ 입실·퇴실 시간, 메모'를 눌러야 입력칸이 열림. **이동시간 자동 채우기**: 경로가 바뀌어 빈 구간은 잠시 뒤 카카오 길찾기 시간으로 채움(집을 지나는 구간 제외), 더보기에 수동 '이동시간 자동 채우기'. **각 날**: 출발 카드 → 이동 배지(미입력은 경고 톤) → 장소 카드(번호·시각·배지, ⋯ 메뉴, 오른쪽 끝 드래그 손잡이) → 숙소 카드(미정이면 경고 테두리) / 마지막 날 귀가 카드. **장소 추가는 오른쪽 아래 플로팅 + 버튼**: 지금 화면에 걸린 날이 기본인 '넣을 날' + 담아 둔 장소 + 검색 시트, 버튼 배지 = 일정에 없는 장소 수(고정 시각인데 일정에 없으면 경고색). 드롭다운은 칸 바로 아래에 열림(`placement="below"`). **메모·입퇴실**(M31, 휴대폰 전용): 숙소는 입실·퇴실 시간(선택)과 '메모 (호실 등)', 다른 장소는 '메모'를 남기고 카드에 회색 줄로 보임(다음 날 출발 카드엔 전날 숙소 퇴실 시각). 장소 상세의 '장소 삭제'는 중립 버튼이고 확인 단계만 빨간색. 지도 시트의 날 선택은 탭 대신 셀렉트. 입력은 바텀 시트(출발·이동 시간·숙소/귀가·장소 추가·지도/차로 보내기), 경고는 해당 카드에 한 줄. 하단: 저장(변경 있을 때) ↔ 경로 보고 차로 보내기, 나갈 때는 자동 저장(M29). 더보기 메뉴: 경로 추천·복제·공유·삭제 |
| 연결 (`/c`) | 진행 바(연결/코드 확인/여행 선택/보낼 정보/보내기) · `SelectableCard` · `Switch` · `MetadataList` |
| 개인정보 (`/privacy`) | 읽기 전용 목록 |

- 다크 모드는 `prefers-color-scheme`를 따릅니다. 화면 확인은 360×640 @3x(=1080×1920)·412×732 @2.625x에서 라이트·다크로 합니다.

## 5. 대비 점검

`python3 tools/contrast.py`가 앱이 실제로 쓰는 토큰 조합을 주간·야간으로 계산합니다.

- 본문·보조 문구·버튼·팝업·QR: 모두 4.5:1 이상 (최저 주간 주 버튼 9.41:1)
- 상태 표시 막대: 주간 주의·정상 2.36:1 (그래픽 기준 3:1 미만)
  - Pleos 토큰에 더 진한 대체 색이 없습니다.
  - 그래서 확인 사항 앞에 항상 "충돌 ·" / "확인 필요 ·" 문구를 붙여 색에만 의미를 맡기지 않습니다.

## 6. QR 인식 시험

| 조건 | 방법 | 결과 |
|---|---|---|
| Pleos 에뮬레이터 2560×1440, 야간 테마, 앱 Landscape 창 | 화면 캡처 → jsQR 해독 | **성공** — 세션 URL과 일치 (`tools/e2e-car.mts`) |
| 주행 시연 중 | 같은 방법 | QR 없음(해독 불가) 확인 |
| iPhone 기본 카메라 / Android 기본 카메라 / 카카오톡·네이버 스캐너 | Mac 화면의 에뮬레이터 QR 촬영 | **미시험** — 실제 폰 필요 |
| 밝기·거리·각도 | 실차 화면 | **미검증** — 실차 확보 불가. Mac 화면은 실차와 반사·각도가 다름 |

인앱 브라우저나 일부 스캐너는 URL fragment를 버릴 수 있습니다. 그러면 휴대폰은 "QR을 다시 스캔해 주세요 · 휴대폰 카메라로"를 보여 줍니다.
