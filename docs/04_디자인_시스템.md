# 04 디자인 시스템

차량은 **Pleos Connect 2.1.5 공식 디자인 에셋**을, 휴대폰은 **Astryx 컴포넌트 + Pleos 모바일 테마**를 따릅니다. 두 화면이 같은 단어를 같은 순서로 보여 주도록 문구를 맞췄습니다.

## 1. 차량: Pleos 토큰 → Compose

| 출처 | 앱에서 쓰는 방식 |
|---|---|
| `design/source/*.fig` (공식 2종) | `design/tools/fig_*.py`로 변수·스타일을 추출 → `design/android-res/` |
| `@color/pleos_*` (232개, 주·야간) | `colorResource(R.color.pleos_*)`. 야간은 `values-night`가 자동 적용 |
| `@dimen/pleos_*` (Connect-S, 791개) | 버튼 높이·패딩·반경, 팝업 폭·반경, 간격(`pleos_common_*`) |
| `TextAppearance.Pleos.*` (24개) | 실행 중 스타일을 읽어 Compose `TextStyle` 생성 (글자 크기 배율·야간 전환 때 다시 읽음) |
| Asta Sans 가변 폰트 | `FontVariation.weight`로 400/500/700/800 |

Gradle `syncPleosRes` 작업이 `design/`의 리소스를 빌드 폴더로 복사해 등록합니다. `design/`이 유일한 출처라서 값이 어긋나지 않습니다.

### 컴포넌트

| 컴포넌트 | 근거 에셋 | 구현 |
|---|---|---|
| `PleosButton` | ivi_basic_button (Primary/Secondary × L/M/S × 눌림/비활성) | `pleos_button_filled_*`/`pleos_button_basic_*` 색, `pleos_buttons_basic_*` 높이·패딩·반경·최소폭 |
| `PleosSystemPopup` | ivi_system_popup (제목·설명·확인/취소) | `pleos_popup_system_medium_width`, 반경 48dp, 그림자 Level3, 설명 3줄 이하 |
| `PleosCard` | 표면 + Shadow/Light/Level1 | `pleos_surface_basic`, 반경 `pleos_radius_l` |
| `PleosHeader` | ivi_title (Main/Depth) | Title Large + 보조 문구 |
| `StatusLine` | informative/regulation 색 | 정상 `informative_active`, 주의 `regulation_orange`, 충돌 `informative_negative` |

### 화면 규칙

- 문장·단락은 3줄 이하입니다(`PleosText` 기본 `maxLines = 3`).
- 주요 정보는 Title Medium(36/44) 이상, 본문은 Body(26~30) 크기입니다.
- 앱 영역 1000dp 이상이면 두 칸(Landscape 1700dp), 미만이면 한 칸(Portrait 840dp)으로 바꿉니다.
- 최상위 Back은 앱을 닫지 않고 숨깁니다(`moveTaskToBack`).
- 주행 중에는 QR·요약·안내 버튼을 숨기고, 시선을 끄는 애니메이션은 쓰지 않습니다.
- 주행 중 여행 상세는 카드 하나(다음 목적지 Title Large + `StatusLine` 한 줄)만 남깁니다. 버튼·스크롤·팝업이 없고, 상태가 바뀌어도 글자만 바뀝니다.
- 시간 지킴이 상태줄은 기존 `StatusLine` 색을 그대로 씁니다: 여유 = positive, 빠듯·확인 불가 = 주의(orange), 늦음 = 충돌(negative). 색만으로 구분하지 않도록 문구에 "여유 66분", "27분 늦을 수 있어요"를 함께 씁니다. 새 색을 추가하지 않아 대비 점검 결과(5장)는 그대로입니다.
- 시연 시각이 켜져 있으면 목록·상세 위에 "시연 시각 11/21 09:00 · 에뮬레이터 전용"을 항상 표시합니다.
- 터치 크기는 공식 dp 값이 없어서 버튼 높이 토큰(Medium 80dp, Large 100dp)을 따릅니다.

## 3. 휴대폰: Astryx + Pleos 모바일 테마

컴포넌트는 Astryx를 그대로 쓰고(접근성·입력 동작 유지), 색·글꼴·모서리는 차량 앱과 같은 **Pleos Connect 2.1.5 공식 토큰**(`design/android-res`)을 휴대폰 크기(차량 dp × 0.6)로 옮겨 입혔습니다(M45). 기준 화면은 FHD 세로 폰(1080×1920, CSS 폭 360–412pt)이고, 넓은 화면에서는 가운데 최대 480pt로 둡니다.

- **테마**(M45 Pleos 재구조화): `src/pleosTheme.ts`를 `astryx theme build`로 `pleos.css`로 만듭니다.
  - 바탕: 회색 캔버스 `background/primary` #F7F8FA(다크 #131417) 위에 흰 컨테이너 `Surface/container`(다크 #1D1E21)를 둡니다. 차량 앱과 같습니다.
  - 강조: 주 버튼·선택은 그래파이트 `button/filled` #44464E(다크 #E0E1E6, 위 글자 잉크), 보조 버튼은 잉크 5%(`button/basic`)입니다.
  - 파랑 `informative/positive`는 정보에만 씁니다: 링크·텍스트 버튼, '고정' 태그, 다음 일차 경로.
  - 스위치 켜짐은 `informative/active` 초록 #02C265입니다.
  - 오류는 `informative/negative` #FE3D16(글자는 대비 맞춘 #D82E08), 고칠 것 표시는 regulation 주황 #FF8A00 점입니다.
  - 모서리: 버튼 S 10 · M/입력칸 14 · 카드 16 · L 버튼 20 · 시트 24. 그림자는 떠 있는 것에만(Pleos Level1·2).
- **글자 사다리**(Pleos Title·Body·Label × 0.6, 굵기 Regular 400·Bold 700만, 자간 0):
  - Title 24/32·22/28·20/26.
  - Body 18/26·17/24·16/24.
  - Label 14/20·12/16.
- **글꼴**: Asta Sans(42dot, OFL)를 93개 가변 조각으로 자체 호스팅해 화면에 필요한 조각만 받습니다. 원격 폰트 참조는 빌드 결과물에 0건이고 CSP는 `default-src 'self'`를 유지합니다.
- **앱 구조**: 왼쪽 정렬 56pt 상단 바(탭 첫 화면은 Title L 24) + 하단 **전폭 평면 탭바**(Pleos GNB처럼 위 구분선, Filled/Outlined 아이콘) 4개(여행 `/` · 장소 `/places` · 연결 `/car` · 설정 `/settings`). 탭에서 여는 화면(여행 편집, `/add`, `/c`, `/privacy`, 설정 하위)은 뒤로 버튼이 있는 푸시 화면이고, 채운 버튼은 화면 아래 하나뿐입니다.
- **새 여행 단계별 안내**(M43): 새 여행은 일차별 일정 대신 4단계 안내로 시작합니다 — 위에 '새 여행 · 2/4'와 진행 막대 4개, 아래 고정 [이전]/[다음]. ① 여행 정보(이름·기간·출발·귀가·밤별 숙소, 이름이 없거나 숙소·미정을 안 고른 밤이 있으면 [다음]이 막히고 아래에 빨간 한 줄) → ② 장소 담기(검색·붙여넣기·직접 입력, 담은 장소마다 [빼기], 즐겨찾기) → ③ 예약·꼭 갈 곳(장소마다 ★꼭 칩, '예약 있음' 스위치 → 날짜·시각(30분 단위)) → ④ 경로 추천([경로 추천 시작] → '장소 위치 확인 → 날짜 나누고 방문 순서 정하기 → 카카오 길찾기로 이동시간 계산'이 차례로 체크되는 진행 화면 → 일차별 미리보기 → [이 일정으로 시작]). 시작해야 일차별 일정·+ 버튼이 나타납니다. '추천 없이 직접 짤게요'로 건너뛸 수 있고, 중간에 나가도 그 단계부터 이어지며 여행 목록에는 '만드는 중 · 2/4'. 숙소 칸은 검색창과 '미정' 칩이 한 줄입니다.
- **이동시간은 카카오로만**(M43): 이동 시간 시트에는 입력칸이 없고 '이동 23분 · 7.3km', '카카오 길찾기 · 14:20 기준', [다시 계산]만 있습니다. 카카오에 물을 수 없는 구간(위치 없는 장소, 설정에 집 주소 없음)은 배지가 중립색 '이동 시간 · 차량 내비가 계산'. **당겨서 새로고침**은 모든 구간을 지금 교통으로 다시 탐색하고, 여행 중(오늘이 여행 날)이면 오늘 일정을 '지금 14:20 출발 기준'으로 다시 계산해 보여 줍니다(화면에서만, 계획의 출발 시각은 그대로).
- **숙소 미입력 · 미정**(M41, toss.md text-field error): 숙소가 없는 밤의 카드는 갈색 경고 대신 **1.5px 빨간 #F04452 테두리**(바탕 틴트 없음)·빨간 침대 아이콘·검색창 아래 **빨간 도움말** '숙소를 입력하거나 미정을 골라 주세요'. 숙소 선택 칩 줄 끝에 **'미정' 칩**(같은 크기의 회색 pill, 누르면 토스 칩 active처럼 어두운 채움·`aria-pressed`) — 누르면 그 밤의 숙소가 필수가 아니게 되어 빨간 표시·일차 머리말 점·보내기 전 확인의 '숙소를 정해 주세요'가 사라지고, 일차 타임라인 끝 카드는 회색 '숙소 미정'. 숙소를 고르면 미정이 풀림. 미정은 휴대폰에만 저장(`lodgingTbd`), 접은 요약은 '숙소 2/3박 · 미정 1박'.
- **장소 검색창**(M38, SOCAR Frame 2.0 `input-filled`의 기본→포커스 표현만 가져옴, `editor/searchBar.css`): 기본은 회색 바탕 #F2F3F8·보이지 않는 1px 보더·모서리 14px·높이 48px·왼쪽 안 돋보기·안내 문구 #99A1B1(16px), 누르면 보더가 연한 파랑 #99CEFF로 나타남. 옆의 '검색' 버튼은 없애고 키보드의 검색/엔터로 찾으며, 찾는 동안 바 안에 로딩이 돌고 오른쪽에 지우기(⊗). 다크 모드는 SOCAR 값이 없어 바탕만 페이지보다 한 단계 밝은 면으로 바꾸고 파란 보더는 그대로. 장소 추가 시트·일차별 숙소·숙소/귀가 시트·/add 직접 찾기·설정 출발 장소가 같은 검색창을 씀. SOCAR의 다른 요소(버튼·칩·색·글꼴)는 쓰지 않음.
- **Pleos 모바일 재구조화**(M45, unslop 무거운 단계 — 사용자 결정: 주 버튼 그래파이트, 다음 여행 카드, 플로팅 + 유지, 일차 칩 바):
  - 여행 탭: 머리 오른쪽 [새 여행] 버튼, **다음 여행 카드**를 둡니다. 진행 중 → 가장 가까운 예정 → 최근 수정 순으로 고릅니다.
    - 카드 내용: 파란 '11일 뒤 출발 / 여행 중 · 2일차 / 지난 여행', 이름 Title M, 기간·박수·장소 수.
    - **전 일정 동선 스케치**(`tripSketch`: 지도 비율 유지, 집 제외, 다음 일차만 파란 실선 + 번호 원, 나머지는 회색 점선 + 점, 숙소는 빈 원).
    - 준비 상태: 주황 점 '미배정 1 · 숙소 1박 입력 전' 또는 '마지막 전송 v1 · 날짜'.
    - 나머지 여행은 '다른 여행' 구분선 목록입니다.
  - 편집기: 상단에 고정된 **일차 칩 바**(여행 정보 · 1일차 · 2일차 …, Pleos Tabs Box, 선택은 그래파이트, 차량 일차 탭과 같음)를 둡니다. 누르면 그 구역으로 이동하고, 스크롤하면 선택이 따라옵니다.
    - 일차 머리말은 고정을 풀고 Title S 제목 + **하루 요약**('운전 55분 · 42.3km · 숙소 도착 16:10 · 이동시간 1구간 미확인', `daySummary`) + [지도]로 바꿨습니다. 거리는 모든 구간에 카카오 거리가 있을 때만 냅니다.
    - 이동은 테두리 알약 대신 레일 위 텍스트 '↓ 이동 15분 · 6.2km'(미확인은 주황 점)입니다.
    - '영업시간 미확인'은 카드에서 빼고 상세에만 둡니다.
    - + 버튼은 그래파이트 원(배지: 흰 바탕, 고칠 것은 주황)입니다.
  - 장소·연결·설정: 섹션마다 흰 컨테이너 하나에 구분선 목록(아이콘은 타일 없이 보조 잉크)을 두고, 폼·안내는 `tn-panel` 컨테이너에 담았습니다.
  - 장소 검색창: M38 동작(바 안 돋보기, 평소 테두리 없음, 포커스 때 테두리)은 그대로 두고 색만 Pleos로 바꿨습니다(잉크 5% 바탕, 포커스 #313236).
- **시트·숙소·여행 목록**(M49)
  - **바텀 시트는 내용만큼**: `Sheet` 기본값을 `hug`로 바꿨습니다. 내용 높이만큼 올라오고 최대 92dvh입니다. 출발 시트는 253px, 숙소 시트는 469px(390×844 기준)입니다.
    - 장소 추가 시트만 `tall`입니다. Astryx는 `tall`일 때만 모바일 키보드에 맞춰 시트 안을 스크롤해, 검색 입력이 키보드에 가려지지 않습니다.
  - **이어서 묵기**(`editor/LodgingSuggest.tsx`): 숙소가 빈 밤에 '이어서 묵기' 라벨과 숙소 칩(침대 아이콘 + 이름)이 나옵니다.
    - 순서는 가까운 앞 밤 → 뒤 밤 → 여행의 나머지 숙소입니다.
    - 숙소를 고른 밤에는 '이후 n박도 이 숙소로' 칩으로 뒤의 빈 밤을 한 번에 채웁니다. 미정으로 둔 밤은 건드리지 않습니다.
    - 여행 정보(새 여행 ① 포함)와 일차 숙소 시트 양쪽에 있습니다.
  - **다른 여행 정렬**: 다가오는·진행 중 여행은 출발일 순(같으면 종료일 → 이름), 그 뒤에 지난 여행이 최근순입니다(`sortOtherTrips`).
  - **날짜 겹침**: 기간이 겹치는 여행 행에 주황 태그 '날짜 겹침 n'을 달고, 부제 끝에 '○○과(와) 겹침 / ○○ 외 n개와 겹침'을 붙입니다. 다음 여행 카드 아래 줄에도 '날짜 겹침 n'이 나옵니다(`dateOverlaps`).
- **출발 시각은 선택 사항**(M48): 모든 날의 출발 시각을 비울 수 있습니다(첫날 포함, 출발 시트의 시각 선택 맨 위 '없음').

## 5. 대비 점검

`python3 tools/contrast.py`가 앱이 실제로 쓰는 토큰 조합을 주간·야간으로 계산합니다.

- 본문·보조 문구·버튼·팝업·QR: 모두 4.5:1 이상 (최저 주간 주 버튼 9.41:1)
- 상태 표시 막대: 주간 주의·정상 2.36:1 (그래픽 기준 3:1 미만)
  - Pleos 토큰에 더 진한 대체 색이 없습니다.
  - 그래서 확인 사항 앞에 항상 "충돌 ·" / "확인 필요 ·" 문구를 붙여 색에만 의미를 맡기지 않습니다.

## 6. QR 인식 시험

| 조건 | 방법 | 결과 |
|---|---|---|
| Pleos 에뮬레이터 2560×1440, 야간 테마, 앱 Landscape 창 | 화면 캡처 → jsQR 해독 | **성공** — 세션 URL과 일치 (`tools/e2e-car.mts`) |
| 주행 시연 중 | 같은 방법 | QR 없음(해독 불가) 확인 |
| iPhone 기본 카메라 / Android 기본 카메라 / 카카오톡·네이버 스캐너 | Mac 화면의 에뮬레이터 QR 촬영 | **미시험** — 실제 폰 필요 |
| 앱 안 스캐너(연결 탭, jsQR) | 헤드리스 Chrome 가짜 카메라(y4m)에 이 앱 형식 QR | **성공** — 권한 허용 → 해독 → `/c` 연결 화면, 다른 QR 거절, 닫으면 카메라 트랙 종료, 권한 거부 안내(M35). 실제 폰 카메라는 미시험 |
| 밝기·거리·각도 | 실차 화면 | **미검증** — 실차 확보 불가. Mac 화면은 실차와 반사·각도가 다름 |

인앱 브라우저나 일부 스캐너는 URL fragment를 버릴 수 있습니다. 그러면 휴대폰은 "QR을 다시 스캔해 주세요 · 휴대폰 카메라로"를 보여 줍니다.
