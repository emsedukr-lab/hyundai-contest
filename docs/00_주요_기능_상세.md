# 떠날지도 주요 기능 상세

저장소 첫 화면 [README](../README.md)의 기능 요약을 자세히 적은 문서입니다.

## 주요 기능

**휴대폰 (모바일 웹)** — 하단 탭 없음 — 메인(여행) 상단의 QR 아이콘(연결)·톱니 아이콘(설정), 플로팅 ＋ 버튼의 여행 추가·장소 추가

- 여행 탭: 다음 여행 카드(D-day·전 일정 동선·준비 상태)와 다른 여행 목록(출발일 순, 날짜 겹침 표시). 왼쪽으로 밀어 삭제하고 8초 안에 되돌립니다.
- 새 여행 4단계 안내: 여행 정보 → 장소 담기 → 예약·꼭 갈 곳 → 경로 추천(날짜 나누기·방문 순서·카카오 이동시간) → [이 일정으로 시작].
- 경로 추천 엔진(`packages/shared/src/optimizer.ts`): 여행 전체를 한 번에 놓고 날짜 배정과 순서를 함께 정합니다(적응형 대규모 근방 탐색 + 담금질, 의존성 없는 TypeScript). 계획 규칙은 이동마다 주차 10분, 예약은 10분 전 도착 후 정각 시작, 문 열기 전·쉬는 시간은 기다림, 쉬는 날·영업시간 밖은 금지, 식사는 식사 시간대(하루 한 번씩), 카페는 하루 2곳까지·점심 뒤가 가장 좋음, 숙소가 바뀌는 날은 퇴실·입실 시간. 이동시간은 잰 값을 먼저 쓰고 없으면 직선거리로 추정한 뒤, 추천 순서의 실제 시간을 받아 한 번 더 계산합니다. 2시간 이상 비는 시간과 입실·퇴실에 걸리는 날은 추천 결과에 알려 주고, 즐겨찾기 가운데 들어갈 만한 곳을 보여 줍니다. 이미 날짜에 넣은 장소는 뚜렷한 이득이 있을 때만 다른 날로 옮기고, 지금 계획보다 낫지 않으면 그대로 둡니다. 새 장소의 머무는 시간은 종류별 기본값(식사 60·카페 45·관광 90분)으로 시작합니다.
- 늦게 출발하기(`lib/laterStart.ts`): 그 날의 첫 예약에 15분 일찍 닿고도 1시간 이상 남으면, 기다리거나 다른 곳을 넣는 대신 **출발을 늦추는 대안**을 일차 제목 아래 카드로 보여 줍니다('오전 11:00에 출발해도 돼요', [오전 11:00 출발]). 숙소를 떠나는 날은 퇴실 시간이 한도이고(입력한 시간, 없으면 통상 11:00이라고 밝힘), 같은 숙소에 또 묵는 날은 한도가 없습니다. 늦춘 시각에 영업시간이 깨지는 곳이 있으면 그보다 이른 시각을 제안합니다. 경로 추천 결과에도 한 줄로 나옵니다.
- 검색한 장소의 종류(관광·산책 / 식사 / 카페·디저트 / 숙소 / 기타)는 카카오 분류에서 정합니다. 카카오가 음식점으로 주는 곳 가운데 간식 갈래는 식사하는 곳이 아니어서 떡·한과 가게 등은 '기타', 제과·아이스크림 등은 '카페·디저트'로 둡니다(이미 담아 둔 장소는 장소 상세의 종류에서 바꿉니다). '꼭 갈 곳'은 3단계에서 핀을 눌러 정하고, 일정에도 같은 핀으로 표시됩니다.
- 편집기: 일차 칩 바, 하루 요약(운전 시간·거리·숙소 도착), 2줄 일정 카드, 끌어서 순서 바꾸기, 밀어서 빼기, 장소 상세 바텀 시트(도착 시각 자유·희망·고정/예약, 머무는 시간 프리셋).
- 시각은 오전/오후 30분 칩에서 고릅니다. 출발 시각은 모든 날 선택 사항입니다. 숙소는 '미정'과 '이어서 묵기' 칩이 있습니다.
- 출발 장소: 1일차는 현재 위치(기본)·집·회사·즐겨찾기 1~3·여행의 장소 중에서 고르고, 2일차부터는 전날 숙소에서 출발합니다. 첫 구간 이동시간은 고른 출발지에서 계산합니다 — 집·회사·즐겨찾기는 설정에 넣은 주소로, '현재 위치'는 허용한 경우 이 휴대폰의 위치(약 100m 단위, 저장·전송 안 함)로. 차량에서는 차량의 현재 위치로 다시 계산합니다.
- 영업시간: 장소마다 '모름 · 따로 없음 · 직접 입력' 중 하나입니다. 직접 입력은 요일별 시간·정기 휴무·쉬는 시간을 담고, 방문 시각이 영업시간 밖이거나 휴무일이면 휴대폰과 차량이 알려 줍니다. 호수·해변·거리처럼 영업시간이 따로 없는 곳은 '따로 없음'으로 두면 차량이 '영업정보 미확인'으로 세지 않습니다. 샘플 '강릉 3박 4일'에는 네이버 지도(2026-11-13)에서 확인한 9곳의 영업시간이 들어 있고, 경포호·안목해변 커피거리는 '따로 없음'입니다.
- 이동시간·거리는 카카오모빌리티 길찾기로만 채우고, 당겨서 새로고침하면 지금 교통으로 다시 계산합니다. 휴대폰의 값은 일정을 짤 때 쓰는 예상값이고, 차량에서는 현대차 내비가 다시 잽니다(구간 시트와 전송 동의 화면에 그렇게 적음).
- 일차 지도는 실제 도로 경로로 그립니다. 예약·고정 시각 앞에는 15분 여유를 둔 'HH:MM 출발'을 표시하고(휴대폰 화면만), 운전이 10분 이상 줄어드는 순서는 '더 빠른 순서' 카드로 제안합니다.
- 지도 앱 공유로 장소 담기, 친구에게 암호화 파일로 여행 공유(서버 미경유), 백업 내보내기·가져오기, 한국어·영어.

**차량 (Pleos Connect)**

- QR 불러오기: 일회용 QR → 6자리 확인 코드 → 재검증 요약 → 결정표(새 여행·업데이트·사본·불러오지 않기).
- 다음 목적지 안내(NaviHelper), 오늘 경로 묶음 전송(남은 장소 모두, 최대 10곳), 이름만 있는 장소는 내비 검색으로 확인.
- 시간 지킴이(내비 남은 시간으로 여유·빠듯·늦음), 건너뛰기·미루기 제안, 자동 도착, '여기서 출발'(내비 예상·도착 시 배터리. 1일차는 출발지를 현재 위치로 바꾸고, 2일차부터는 전날 숙소 출발을 그대로 둠), EV·연료 권장.
- 1일차 첫 구간 자동 계산: 계획에 첫 구간 이동시간이 없으면(출발지가 '현재 위치'이거나 휴대폰에 집 주소가 없을 때) 주차 중 여행을 열 때 내비에 현재 위치 기준 예상을 물어 채웁니다. 버튼을 누르지 않아도 1일차 시각이 계산됩니다.
- 현대차 내비로 전 구간 측정: 차량에서는 내비가 잰 값이 구간의 시간·거리입니다. [전 구간 내비로 측정]을 누르고 확인하면 내비에 경유지 경로를 걸어 구간별 시간·거리를 읽고 경로를 지웁니다(`requestTrip`은 차가 있는 곳에서만 재므로, 떨어진 구간은 경유지별 남은 값의 차이로 구함). 잰 구간은 '↓ 7분 · 3.0km · 내비', 하루 요약은 '운전 37분 · 17.0km'로 표시됩니다. 샘플 여행 13구간이 경로 2번, 약 30초입니다.
- 내비 기준 순서 최적화: [N일차 순서 최적화]는 그 날 장소 사이의 모든 구간을 내비로 재고 가장 빠른 순서를 찾습니다. 운전이 10분 이상 줄고 시간표 충돌·예약 15분 여유를 해치지 않을 때만 제안하며, [이 순서로 바꾸기]는 차량에서만 순서를 바꿉니다(휴대폰이 보낸 계획은 그대로, [계획 순서로 되돌리기]).
- '오늘 경로 전송'은 남은 장소를 모두(최대 10곳) 경유지로 보냅니다(2026-11-13 전에는 3곳).
- 차량 신호 조합(모두 조회 전용): 출발 전 점검(주행가능거리 × 오늘 남은 거리, 탑승 × 안전벨트, 문·트렁크, 충전 포트 등), 일정 끝 배터리 예상, 2시간 연속 운전 시 쉬어 가기 권고(휴게소 거리·일정 여유와 함께), 오늘 경로를 보낸 뒤 경유지마다 도착 표시·다음 장소 기준 도착 예정, 가는 길 정체. 무엇을 써서 무엇을 만들었는지는 [docs/research/04_Pleos_SDK_API_활용.md](research/04_Pleos_SDK_API_활용.md).
- 주행 중에는 QR·승인 화면을 숨기고 다음 목적지 카드 하나만 보여 줍니다.

## 시험 명령 전체

```sh
npm test                    # shared 111 · worker 53 · web 172 (TypeScript 336)
npm run typecheck
(cd car && ./gradlew test)  # Kotlin 221 (car 모듈)
npm run smoke               # 서버 흐름 (기본 http://localhost:8787, 다른 주소는 `npm run smoke -- <URL>`)
npm run e2e                 # Chrome 휴대폰 + 가짜 차량 (같은 방식으로 주소 지정, 화면은 docs/evidence/m3/에 덮어씀)
npm run e2e:car             # 에뮬레이터 차량 앱(dev debug) + Chrome 휴대폰 (기본 emulator-5580)
npx tsx tools/live-pair.mts # 서명 release APK + 배포된 모바일 웹·서버 실제 연동, 양쪽 화면을 docs/evidence/live-pair/에 저장
npx tsx tools/fleet-webhook-sample.mts       # Fleet 웹훅 예시 payload → 로컬 wrangler dev (토큰은 .dev.vars, 파일 머리말 참고)
npx tsx tools/phone-test.mts                 # 실제 폰 + 가짜 차량 (Mac 화면에 QR 표시, 기본 배포 서버)
npx tsx tools/record-demo.mts emulator-5580  # release APK + 배포 서버 전체 흐름 녹화·메모리 기록
npx tsx tools/compose-demo.mts               # 녹화 → media/demo/떠날지도_시연.mp4
npx tsx tools/compose-shorts.mts             # 녹화 → media/demo/떠날지도_숏폼.mp4 (세로)
```

2026-11-15 기준 TypeScript 392개와 Kotlin 221개가 모두 통과하고, 모바일 E2E(`npm run e2e`, 15항목)와 차량 에뮬레이터 E2E(`tools/e2e-car.mts`, 16항목)도 통과합니다. 같은 날 서명 release APK 0.6.0과 배포 서버·모바일 웹의 실제 연동(`tools/live-pair.mts`, 15항목)을 다시 확인했습니다([다음 목적지 안내]로 Pleos 내비가 경로 안내를 시작하는 것까지 0.6.0으로 확인) — 화면은 `docs/evidence/live-pair/overview.png`(2026-11-13 0.6.0으로 다시 저장). 출발지 규칙과 영업시간 화면은 `docs/evidence/m59`에, 내비 측정·순서 최적화 화면은 `docs/evidence/m63`에 있습니다. 전송 스키마를 바꾸면 `npm run schema`로 JSON Schema·fixture를 다시 만들고 TS·Kotlin 시험을 모두 돌립니다.
