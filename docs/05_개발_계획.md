## 3. 실제 동작과 시연용의 구분

| 항목 | 실제 동작 | 시연·대체 |
|---|---|---|
| QR·세션·암호화·결정표 | 실제 서버·실제 암호화 | — |
| 서버 | 배포 서버에서 스모크·브라우저 E2E 통과, release APK(에뮬레이터)와 배포 서버로 전체 흐름 통과 | — |
| 휴대폰 | Chrome(Playwright, 390×844 휴대폰 화면)으로 자동 시험 | 실제 폰 카메라 스캔과 실제 폰에서의 새 화면 점검(당겨서 새로고침·밀어서 삭제·시각 시트·지도) 미완 |
| 차량 | Pleos Connect Emulator 2.1.0 | 실차 미검증 |
| 주행 잠금 | `CarUxRestrictions` 코드 경로 구현 | 에뮬레이터 VHAL 주입이 막혀 시연 스위치(debug·에뮬레이터 전용)로 화면 검증 |
| 내비 안내 | 에뮬레이터의 실제 Pleos 내비가 경로 안내 | 위치는 에뮬레이터 기본값(성남) |

## 4. 시험 전략

- **계약 시험**: `schema/fixtures`를 TS와 Kotlin이 함께 읽어 같은 판정을 내는지 확인합니다. 스키마를 바꾸면 `npm run schema`로 fixture를 다시 만듭니다.
- **상태 머신**: 서버 전이(`transition`)와 차량 리듀서(`CarHandoffMachine`)를 순수 함수로 두고 표 형태로 시험합니다.
- **실행 환경 시험**: 중계 서버는 workerd(`@cloudflare/vitest-pool-workers`)에서 짧은 유효시간으로 만료·묘비 삭제까지 실제 시간으로 확인합니다.
- **E2E**: 브라우저(가짜 차량)와 에뮬레이터(실제 차량 앱 + Chrome 휴대폰)로 흐름 전체를 돌리고, 화면을 `docs/evidence/`에 남깁니다.
- **현재 결과**: TypeScript 484(shared 119 · worker 76 · web 289, 2026-11-19), Kotlin 225(2026-11-15) 모두 통과. 아래 E2E·실제 연동은 2026-11-15까지 돌린 결과입니다. 모바일 E2E(`npm run e2e`) 15항목·차량 에뮬레이터 E2E 16항목, 서명 release APK ↔ 배포 서버 실제 연동 15항목(`tools/live-pair.mts`, 화면 `docs/evidence/2026-11-10_live-pair/`).
