# 03 개인정보 설계

원칙은 세 가지입니다.

1. 여행은 만든 기기에 둡니다.
2. 옮길 때는 하나만, 사용자가 고른 범위만, 종단간 암호화해서 옮깁니다.
3. 옮긴 뒤에는 중간에 아무것도 남기지 않습니다.

## 1. 데이터 목록

| 데이터 | 휴대폰 | QR | 중계 서버 | 차량 |
|---|---|---|---|---|
| 여행 계획 (이름·기간·장소·순서·시간·숙소) | IndexedDB, 이 브라우저만 | 없음 | 암호문, 세션 종료 즉시 삭제 (최대 약 25분) | Keystore로 암호화한 파일 |
| 집 주소·좌표 | IndexedDB (선택 입력) | 없음 | 동의한 경우에만 암호문 안에 | 받은 경우 여행 파일 안. 없으면 내비 '집'(사용자 확인 후) |
| 세션 식별자·스캔 비밀값 | 연결 기록 (끝나면 삭제) | sid·비밀값·차량 키 지문 | sid, 비밀값 해시 (claim 즉시 삭제) | 세션 저장소 (끝나면 삭제) |
| 토큰 | mobileToken (끝나면 삭제) | 없음 | 해시만 | carToken (끝나면 삭제) |
| 공개키 | 자기 키 | 차량 키 지문 | 양쪽 공개키 (종료 시 묘비만 남고 10분 뒤 삭제) | 자기 키·휴대폰 공개키 |
| 상태 묘비 | — | — | 상태·결과 코드·시각, 10분 | — |
| 보낸 기록 | 여행 ID·버전·시각·결과 (차량 식별정보 없음) | — | — | — |
| 방문 기록·내비 장소 연결 | — | — | — | 여행 오버레이 |
| 장소 검색어 | — | — | 카카오로 전달만, 저장·로그 없음 | — |

차량명·번호판·차량 ID·계정 정보는 어디에도 없습니다. 연결 대상은 확인 코드와 세션으로만 구분합니다.

## 2. 보내지 않는 정보

전송 스키마에 칸이 없어서 보낼 방법 자체가 없습니다. 모든 객체가 `additionalProperties: false`입니다.

- 계정·로그인 정보, 결제 정보, 예약번호·예약 비밀번호, 메모
- 휴대폰의 다른 여행
- 위치 이력

휴대폰은 화이트리스트 매퍼로만 전송 데이터를 만들고, 차량은 모르는 필드가 있으면 거절합니다.

## 3. 집 주소 동의

- 여행 편집에서 집 주소는 선택 항목이며 "이 휴대폰에만 저장돼요"라고 안내합니다.
- 보낼 때 "집 주소 포함" 스위치가 **기본 꺼짐**입니다. 꺼져 있으면 "차량 내비게이션의 '집'을 사용해요"라고 알려 줍니다.
- 차량 요약 화면에 "집 주소 포함/미포함(내비 '집' 사용)"을 표시합니다.
- 내비 '집'은 사용자가 "내비의 '집'을 사용할까요?"에 동의해야 연결되고, 그 여행의 출발·귀가에만 씁니다.

## 4. 삭제 경로

| 위치 | 방법 |
|---|---|
| 휴대폰 | 여행 편집 → 이 여행 삭제 / 브라우저 사이트 데이터 삭제 |
| 중계 서버 | 자동: 종료 즉시 암호문 삭제, 10분 뒤 기록 전체 삭제 (`deleteAll`) |
| 차량 | 여행 상세 → 이 여행 삭제 / 설정 → 모든 여행 삭제 / 지난 여행에 "렌터카·공용 차량이면 삭제" 안내 |
| 시연 데이터 | 실제 데이터와 별도 폴더 |

계정·기기 연결이 없으므로 "연결 해제" 절차가 필요 없습니다. 지속 동기화를 도입한다면 [02 기술 구조 9절](02_기술_구조.md#9-향후-설계-지속-동기화-미구현)의 해제·삭제 설계를 따릅니다.

## 5. 위협 모델

| 위협 | 대응 |
|---|---|
| 남이 QR을 촬영 | 5분 만료, 1회 claim. 먼저 claim해도 차량·휴대폰 코드 비교 단계에서 걸리고, 여행은 정상 사용자가 고르기 전엔 보내지지 않음 |
| 어깨너머로 코드 보기 | 코드는 비밀이 아니라 일치 확인용. 공격자가 같은 코드를 만들려면 ECDH 키를 바꿔야 하고, 그러면 코드가 달라짐 |
| 중계 서버 침해·운영자 | 서버는 암호문만 가짐(키는 양쪽 기기에만). 키를 바꿔치기하면 QR 지문과 확인 코드가 맞지 않음 |
| 재전송·재사용 | 세션마다 새 키, AAD에 sid. 다른 세션에 같은 암호문을 넣어도 열리지 않음(시험) |
| 중간자 | TLS 1.2+, release 빌드 평문 금지, QR fragment의 공개키 지문 |
| 무차별 대입 | 128bit sid·비밀값, 세션당 claim 5회, IP별 요청 제한 |
| URL 유출 (기록·리퍼러) | 비밀값은 fragment에만, 읽은 즉시 주소창에서 제거, `Referrer-Policy: no-referrer` |
| 차량 저장소 탈취 | Keystore 키로 AES-GCM 암호화, 백업·기기 이전 제외 |
| 로그 | 요청 본문·토큰·검색어를 로그에 남기지 않음. 차량 QR URL 로그는 debug 빌드에서만 |

## 6. 제3자

| 제3자 | 목적 | 전달되는 것 |
|---|---|---|
| Cloudflare | 중계 서버·웹 호스팅 | 암호문, 세션 메타데이터, 접속 IP(요청 제한용, 저장 안 함) |
| 카카오 | 장소 검색 | 검색어 (사용자가 검색할 때만) |

## 7. Pleos 가이드 대응

| 가이드 (02_PLEOS_개발자가이드 1.7·9.x) | 대응 |
|---|---|
| 토큰은 Keystore 등 안전한 저장소에 | 세션 토큰·키는 `SecureBox`(Keystore AES-GCM)로 암호화 |
| 불필요한 개인정보 저장 금지, 로그 마스킹 | 위 표와 같음. 로그에 본문·토큰 없음 |
| 운전자 교체·공유 차량 대비 | 계정 없음, 여행 단위 삭제, 지난 여행 삭제 안내 |
| URL 경로·쿼리에 토큰 금지, TLS 1.2+ | fragment와 헤더만 사용 |
| 앱 심사용 개인정보처리방침 URL | 웹 `/privacy` |

## 8. 안내 문구 (실제 화면)

- 휴대폰 홈: "여행은 이 휴대폰 브라우저에만 저장돼요. 계정이 없고 서버에 보관하지 않아요. 차로 보낼 때만, 고른 여행 하나가 암호화되어 잠시 전달돼요."
- 연결 요청: "이 연결은 여행 하나를 한 번 보내는 데만 쓰이고, 계정이나 기기 연결이 남지 않아요."
- 차량 QR: "QR에는 여행·개인정보가 없어요 · 5분 동안 한 번만 쓸 수 있어요"
- 차량 설정: "불러온 여행은 이 차량에만 암호화해 저장해요. 계정 연결이나 휴대폰과의 계속 동기화는 없어요." / "렌터카·공용 차량을 반납하기 전에는 여행을 모두 삭제해 주세요."
