# NaviHelper 경유지 값으로 구간 시간·거리 구하기 (2026-11-13 확인)

질문: `requestTrip`은 "차량 현재 위치 → 목적지"만 답한다. 경유지 경로(`requestRouteWithWaypoints`)를 걸고 내비가 돌려주는 경유지별 남은 시간·거리의 **차이**를 내면, 차가 있지 않은 곳 사이(예: 집 → 1일차 숙소, 장소 → 장소)의 값을 얻을 수 있는가?

시험 환경은 Pleos Connect Emulator(내비 위치 성남 수정구 시흥동, 금요일 17:00~17:05)와 debug 빌드의 `NaviProbe`다. 서명 앱과 여행을 건드리지 않도록 debug 빌드를 다른 패키지로 나란히 설치했다.

```sh
cd car && ./gradlew :app:assembleDevDebug -Ptteonaljido.debugIdSuffix=.probe
adb -s emulator-5580 install --user 10 -g app/build/outputs/apk/dev/debug/app-dev-debug.apk
adb shell am start --user 10 -n io.tteonaljido.car.probe/io.tteonaljido.car.MainActivity --es probe "via:<lat,lon>|<lat,lon>|…"   # 마지막 점이 목적지
adb shell am start --user 10 -n io.tteonaljido.car.probe/io.tteonaljido.car.MainActivity --es probe "waypoints"                 # 이어서 destination, cancel
```

- **된다.** `onDrivingInfo.waypoints`·`getWaypointInfo`의 값은 현재 위치에서 각 경유지까지의 누적값이고, 이웃한 값의 차이가 그 구간의 시간·거리다. T1의 첫 경유지 값(4800초·22km)은 같은 곳을 `requestTrip`으로 물은 값(4747초·22.4km)과 맞는다.
- **경유지는 2곳보다 많이 실린다.** SDK의 `WaypointIndex`에는 `FIRST`·`SECOND`뿐이지만, 세 번째부터 `SECOND`로 보내도 보낸 순서 그대로 3·5·9곳이 모두 실렸다(순서를 바꾸지 않음). 같은 장소를 되풀이해도 받는다(T7) → 한 경로로 양방향 구간도 얻는다.
- **조회가 아니라 실제 안내 시작이다.** 요청마다 `onRouteStarted` → `ROUTE_DRIVE`가 오고 내비 화면이 턴 안내로 바뀐다(`01-nine-waypoints-guiding.png`). 쓰던 경로가 있으면 지워진다. 끝나면 `cancelRoute`로 지워야 한다.
- **한 번에 하나다.** 새 요청이 오면 앞 경로가 `onRouteCancelled`로 지워진다. 요청에서 `onRouteStarted`까지 9~11초, 경유지 9개 값이 다 보이기까지 약 20초(200km 경로 기준).
- **값은 분·km 단위로 깎여 있다**(60초·1000m의 배수, 200km 떨어진 곳에서 본 값). 같은 구간이 한 경로 안에서 8분·7분으로 달랐다(T7) → 구간마다 ±1분·±1km.
- **카카오보다 짧게 나온다.** 강릉 시내 구간이 카카오의 68~78%였다(금요일 17시). 엔진이 달라 어느 쪽이 맞는지는 이 시험으로 알 수 없다. 장거리(T1)는 4% 차이.
- **지금 교통 기준이다.** 며칠 뒤 구간도 요청한 순간의 교통으로 계산된다(카카오도 같다).

## 확인하지 못한 것

- 실차 내비가 경유지를 몇 곳까지 받는지(에뮬레이터 내비 기준 9곳까지만 시험). SDK 문서는 "내비 앱의 구현에 따라 다를 수 있다"고만 한다.
- 안내 시작 때 음성이 나오는지, 주행 중 요청이 어떻게 처리되는지.

시험 뒤 `cancel`로 경로를 지웠고(`FREE_DRIVE`, 목적지 없음) probe 패키지를 제거했다. 앱 동작은 바꾸지 않았다('오늘 경로 전송'은 지금도 경유지 2곳 + 목적지).
