# 06 시연 시나리오 (2차 PT, 5~7분)

## 준비

| 항목 | 내용 |
|---|---|
| 차량 | Pleos Connect Emulator 2.1.0, cold boot, 떠날지도 prod APK, 기어 P |
| 휴대폰 | 실제 스마트폰 1대(기본 카메라) + 예비 1대(재사용 거부 시연용) |
| 서버 | 배포된 Worker(별도 staging 서버는 없음). 카카오 장소 검색·길찾기 키 등록, 지도 JS 키를 넣은 웹 빌드 |
| 네트워크 | 행사장 Wi-Fi + 휴대폰 핫스팟 예비 |
| 사전 데이터 | 휴대폰에 '강릉 3박 4일' 샘플 여행(`/?sample=1`로 추가)과 ③단계까지 채운 '만드는 중 · 3/4' 여행 하나(기간은 샘플보다 뒤로 잡아 다음 여행 카드에 샘플이 오게 함). 차량은 여행 0개 |
| 휴대폰 설정 | 집 주소는 비워 둠. 넣으면 카카오가 1일차 집 → 첫 장소 구간을 채워, 차량 '여기서 출발' 장면에서 채워질 구간이 없어짐 |
| 리허설 확인 | '더 빠른 순서' 카드: 샘플 그대로는 이미 빠른 순서라 뜨지 않음. 3일차 두 장소(교동반점·테라로사)를 끌어서 순서를 바꾸면 카카오 실제 시간으로 '운전 12분 줄어요'가 뜸(2026-11-10 배포 서버에서 확인). 일차 지도에 도로 경로가 그려지는지 |
| 시연 장치 | 설정 → 시연 카드: 시연 시각(2일차 09:00), 도착 신호(시연). 에뮬레이터 내비는 움직이지 않으므로 사용하며, 화면에 '시연'이 표시됨을 말로도 밝힘 |
| 예비 자료 | 전체 흐름 녹화 영상 `media/demo/떠날지도_시연.mp4`(3분 45초, 2026-11-10 지금 화면: 동선 자동 구성 → 차량 불러오기 → 내비 안내), 세로 숏폼 `media/demo/떠날지도_숏폼.mp4`(56초, 2026-11-05 녹화라 휴대폰은 예전 화면) |
| 에뮬레이터 | `-gpu host`로 cold boot (소프트웨어 렌더링이면 시스템 화면이 멈춤). 내비 안내가 남아 있으면 '안내 종료' |

| ④ 경로 추천이 느림 | '추천 없이 직접 짤게요'로 넘기고 샘플 여행으로 이어감 |
| '더 빠른 순서' 카드가 뜨지 않음 | 카카오 시간으로 10분 이상 줄지 않으면 띄우지 않는 것이 정상이라고 말하고, 배포 서버에서 찍은 예시 화면 `submission/img/phone-faster.png`를 보여 줌 |

## 정직하게 밝힐 범위

- 실차와 실제 주행 중 사용성은 검증하지 못했습니다. 에뮬레이터와 Mac 화면 기준입니다.
- 휴대폰 화면의 자동 시험은 Chrome의 휴대폰 크기 화면 기준입니다. 실제 폰 점검은 남은 작업입니다.
- 샘플 장소 좌표는 시연용 근사값입니다. 휴대폰의 이동시간은 카카오 길찾기로만 채우고(샘플에 미리 넣은 값은 당겨서 새로고침하면 카카오 값으로 바뀜), 영업시간은 사용자가 입력한 값만 씁니다.
- 고정 시각 앞 15분 여유와 '더 빠른 순서'의 10분 기준은 우리가 정한 값이고 휴대폰 화면에만 씁니다. 차량 시각표와 시간 지킴이는 고정 시각을 그대로 기준으로 합니다.
- 지속 동기화는 구현하지 않았습니다(설계만 있음).
- 주차 소요시간은 지금 계산에 넣지 않습니다. 실차에서 내비 안내 종료 뒤 시동 종료·안전벨트 해제·문 잠금으로 실제 도착을 잡아 장소 종류별 주차 시간을 추정하는 것은 향후 계획입니다(기술 구조 §10).
